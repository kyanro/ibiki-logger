# README画像の更新

READMEの3枚は、固定した架空のデータを実際のCompose UIに表示して撮影する。個人の録音・検出結果は使わない。画像への文字や端末フレームの合成は行わず、アプリ内の表示領域を直接PNGとして取得する。通知・OSの時計・ナビゲーションバーは撮影範囲に含めない。

| ファイル | 内容 |
| --- | --- |
| `images/home.png` | 録音開始と感度設定 |
| `images/timeline.png` | 固定タイムラインと記録の概要 |
| `images/clips.png` | 時刻指定で移動した区間、位置線、波形 |

画像名にバージョン番号を入れず、日英のREADMEから同じパスを参照する。外見が変わらない更新ではそのまま利用できる。UIを変更した場合は撮り直し、同じファイルを差し替える。

## 撮影

Windowsのビルド環境と、ロック解除済みのAndroid端末またはエミュレーターが必要。端末が1台なら次のコマンドで撮影できる。

```powershell
.\scripts\capture-readme.ps1

# 複数台の場合は使用する端末を指定
.\scripts\capture-readme.ps1 -Serial <device-serial>
```

スクリプトは撮影専用ビルドを生成し、一時インストール・撮影・画像取得を行って、撮影専用アプリを片付ける。正常終了すると`docs/images/`の3枚が更新される。失敗時の出力は`artifacts/readme-screenshots/`に残る場合がある。

- 撮影用のアプリIDは`com.kyanro.ibiki_logger.screenshots`、テスト用は末尾に`.test`を付けたもの。通常版のインストールやデータを使わない。
- 既に撮影用アプリが入っている場合は停止する。前回が途中で終了した場合は、撮影用の2パッケージだけを削除して再実行する。
- 架空の記録は1月1日22:30開始、8時間、72区間で固定。波形・スコアもプログラムで生成する。録音の検出性能を示すデータではない。
- 撮影中のフォント倍率は1倍。端末の設定自体は変更しない。画面解像度と密度は撮影端末に従うため、同じ端末・縦向きで撮ると比較しやすい。
- 画面取得用のコードは`src/androidTestScreenshots/`にあり、通常版のAPKや通常の実機テストには含まれない。
- 撮影後は3枚を開き、文字切れ、読み込み途中の波形、選択位置、画面の並びを確認する。

## 翻訳の更新

説明の変更は`README.md`の日本語版を先に更新し、同じ変更に対応する`README.en.md`も更新する。新しい画像を使うだけなら、画像を差し替えることで両方へ反映される。英語版にも、表示データが架空でありUIは日本語であることを明記する。

日本語を原文とする方針はREADMEの説明にのみ適用する。`LICENSE`、音源の権利表示、第三者ライセンスの原文はそのまま保持する。
